# 做过哪些选择，为什么

这份文档记录项目里做过的重要选择，以及当时的理由和代价。

**规则：已经写下的条目不修改。** 如果后来推翻了某个选择，就新加一条，然后把旧那条的状态改成「已被第 N 条取代」。这样能看到想法是怎么变的，避免过一阵子又把同样的弯路走一遍。这个项目早期目标改过四次，所以这件事特别有必要。

每条的格式：状态 / 当时的情况 / 决定 / 为什么 / 代价是什么。

不认识的词查 [`GLOSSARY.md`](GLOSSARY.md)。

## 1. 从「判断是不是某个人」改成「把像的归到一起」

**状态**：有效（2026-09-05）

**当时的情况**：上一版项目的做法是「事先指定一个目标角色，然后判断每个片段是不是他」。实际用起来发现，真正想要的是「把一集拆成按人分好的组」，而且有几个人、都是谁，事先根本不知道。

**决定**：核心算法从「判断是不是他」改成「把像的归到一起」，输出是若干个组，组数由程序自己估。

**为什么**：老做法要求给每个目标准备正反例，换个角色就得重来一遍。更要命的是「不是目标的那些人」是无穷无尽的（新角色、旁白、路人），按「就这么几类」来建模，换一集就会大面积判错。

**代价**：评估指标要换成专门衡量分组好坏的那种；多出一个「把各集的组连起来」的环节，而这个环节没有现成方案，必须自己写；还必须设计人工修改功能，因为自动分组一定会出错。

## 2. 按「角色」收集，不按「配音演员」

**状态**：有效（2026-09-05）

**当时的情况**：同一个配音演员会在一部作品里配好几个角色，也会在不同作品里配不同角色。收集单位可以选角色，也可以选人。

**决定**：按角色。

**为什么**：最终目的是收集音色。同一个配音演员配不同角色时，音区和演法差别很大（比如同一个人配的少年角色和傲娇少女），混进同一个数据集会让音色变得不统一。按角色收集，得到的才是一个自洽的声音。这不是「因为容易所以选它」，而是对目标更准确的理解。

**代价和好处**：好处是不再要求跨作品也能认对，评估划分单位可以放宽到「按集分」。另一个好处是「模型可能是在认录音环境而不是认音色」这个担忧基本消失了，因为每个角色本来就要单独处理，模型学到「这部作品的录音特征 + 这个角色」并不碍事。唯一还要防的是把同作品的其他角色认成目标。

## 3. 只要声音，不要文字

**状态**：有效（2026-09-05，取代了中间短暂存在过的「做 TTS 素材」这个假设）

**当时的情况**：一度以为最终用途是语音合成，所以设计里带了语音转文字和文字对齐。后来确认了实际用途是音色模型（RVC、so-vits-svc 这一类），它们不需要文字。

**决定**：流程里不要语音转文字、不要文字对齐、不要转写清单。字幕降级成可有可无的参考，字幕是中文还是日文都无所谓。

**为什么**：音色模型不需要文字。留着语音转文字会引入一整条又贵又容易出错的链路（动画配音的情绪化发音对识别是难点），而收益是零。

**代价**：没有代价，这一改纯粹是做减法。顺带还消掉了「字幕语言是什么」这个待定问题。

## 4. 分析用低采样率，成品用原采样率，两条路分开

**状态**：有效（2026-09-05）　**这是全项目最不能犯的错**

**当时的情况**：说话人分段和声音指纹这些模型都在 16 kHz 上工作，而音色模型大多在 40 到 48 kHz 上训练。

**决定**：16 kHz 单声道副本**只用来分析**，往下只传「时间点和组号」。成品音频永远拿着时间点回到原始采样率的音轨去切。配置项 `export_sample_rate` 默认是「保持原样」，而不是某个具体数值。

**为什么**：把降过采样的音频再升回去，高频已经永久丢了，补不回来。而且这种损坏**听着不明显、程序也不报错**，属于「毁了都很难发现」的那类问题。

**代价**：流程里要同时维护两条音频路径，实现稍微麻烦一点。另外两个可以参考的开源项目（Emilia-Pipe 会统一转成 24 kHz，TTSizer 是给语音合成用的）在导出这一步都不能照抄。

## 5. 新建仓库，不在老仓库上改

**状态**：有效（2026-09-05）

**当时的情况**：老仓库的 `.git` 有 91 MB（121 MB 的音频文件全提交进历史了），而且代码建立在已经被推翻的假设上。可选方案是清理历史后重构，或者干脆另起一个仓库。

**决定**：新建 `anime-voice-sorter`，老仓库原样不动。

**为什么**：老代码没有能复用的部分，特征提取、模型、评估、输出全都基于「判断是不是某个人」这个已经作废的思路（见第 1 条）。既然是重写而不是重构，那就没必要去改写一个公开仓库的历史、让已有的 fork 和 PR 链接全部失效。

**代价**：老仓库那 91 MB 历史还在，但已经不影响新工作了。老代码的问题清单压缩后搬到了 [`OLD_PROJECT.md`](OLD_PROJECT.md)。

## 6. 所有片段走同一套处理，不挑着来

**状态**：有效（2026-09-05，这一条修正了更早的一个错误判断）

**当时的情况**：早先判断过「背景音乐重的片段就抠人声，轻的直接用原音轨，逐条选最好的」。

**决定**：选定一套处理方式，全部片段都走它。默认是全部都抠人声。

**为什么**：两套处理方式混在同一个数据集里，音色模型会学到不一致的杂音特征。数据集内部的一致性，比任何单条片段的绝对质量都重要。而且动画里真正没有背景音乐的对白很少，所以默认全抠。

**代价**：本来可以保留原始音质的少数干净片段，也得跟着承受一次抠人声带来的伪影。所以表里要记 `pipeline_hash`，将来成品有问题时能查出是哪一批设置不一样。

## 7. 切段以说话人分段为准，字幕只当参考

**状态**：有效（2026-09-05）

**当时的情况**：字幕时轴是免费的现成资源，直觉上就该拿它来切片，上一版项目正是这么做的。

**决定**：以说话人分段的结果为主。字幕只用来**核对**（落在字幕空白处的声音多半是音效残留，标记出来降权），不用它定边界。没字幕也照样能跑。

**为什么**：字幕有两个致命毛病。一是**只有台词**，惊呼、笑声、喘息这些对音色恰恰很有用的声音，字幕里根本没有；二是一行字幕常常横跨两个人说的话，而且边界还差 100 到 300 毫秒。

**代价**：必须跑说话人分段模型，比直接按字幕切要慢。

## 8. 分组分两层做

**状态**：有效（2026-09-05）

**决定**：第一层用一集内部的分组结果；第二层拿每个组的**中心点**做层次聚类，把跨集的同一个人连起来。不要把整部动画所有片段一次性丢进去分。

**为什么**：一个中心点是几十秒到几分钟语音的平均值，比单独一个 1.7 秒片段的指纹稳定得多。而且计算量从「片段数的平方」降到「组数的平方」。

**代价**：第一层的错误会被带到第二层，需要靠人工修改环节兜底。

## 9. 使用者给的样本主要用来定分界线，起名字是次要用途

**状态**：有效（2026-09-05）

**当时的情况**：使用者可能会提供少量样本。直觉上它的用途是「事先告诉工具有哪些人」。

**决定**：**不要求**使用者事先提供样本。正确的顺序是先分组，再让使用者给组起名。样本是可选的加速通道，它最主要的用途是帮忙定分组的相似度分界线，起名字是次要的。

**为什么**：分组做完之后，每组只要听三五条代表样本就能认出是谁，比事先去翻找样本快得多。而那个分界线是整个工具最关键、也最难凭空定的数字，每人两三条样本就能把它从「猜」变成「算」，这对最终效果的影响比起名字大得多。

**代价**：没有代价，这纯粹是让工具更好用。可以对照 TTSizer，它要求在配置文件里事先写死角色列表，正是我们要避开的样子。

## 10. 主动放弃只说一两句的路人

**状态**：有效（2026-09-05）

**决定**：设一个最短总时长（默认 60 秒），低于它的组全部并进 `_misc/`，不再费力区分。

**为什么**：一部动画有 5 到 15 个常驻角色，外加一大堆只有一两句台词的路人。路人的两句话没有收集价值，而试图把它们一一区分开，会明显拉高分组难度和你的复核工作量。

**代价**：偶尔会误伤台词很少但你确实想要的配角。这个时长可以调，而且 `_misc/` 里原始片段都在，事后能捞回来。

## 11. torch 按操作系统分别指定下载源

**状态**：有效（2026-09-05）

**决定**：在 `pyproject.toml` 里配两个下载源，按操作系统分流：Windows 装 CUDA 12.8 版本，其他系统装纯 CPU 版本。torch 和 torchaudio 都锁在 2.11。

**为什么**：开发用的这台机器有独立显卡，需要 CUDA 版本；而自动检查跑在 Linux 上，如果也去下 CUDA 版本，每次都要下载 2.6 GB。锁死版本是因为第一次生成锁文件时，解出了 torch 2.14 配 torchaudio 2.11 这种不兼容的组合。

**代价**：以后升级 torch 时要同时改两处版本限制。

## 12. 人工修改界面先看看有没有现成的

**状态**：待验证（2026-09-05）

**当时的情况**：原计划自己写一个网页界面。调研时发现 `voxmap-studio`（2026 年，开源）已经能做调整边界、拆分、删除、重新指派，而且明确支持跨文件的统一人物编号，还有一个我们没想到的功能：自动高亮「跟别的组更像」的片段，把注意力引到最可能标错的地方。

**决定**：动手写之前先花半天试试它，能用就不自己写。

**为什么**：它的功能已经覆盖了我们的需求，而且那个自动高亮的设计比我们原来的想法更好。能用的话省一天。

**代价**：论文里没给仓库地址，得先找到代码。如果最后用不了，就退回自己写，损失是评估花掉的半天。
