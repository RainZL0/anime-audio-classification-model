# 决策记录

> 追加式文档：**不修改已有条目**。决策被推翻时，追加新条目，并把旧条目状态改为「已取代 by ADR-NNN」。
> 决策的演变过程本身有价值，尤其是这个项目的目标在早期改过四次。

格式：状态 / 背景 / 决定 / 理由 / 代价。

## ADR-001　目标从「二分类」改为「聚类」

**状态**：生效（2026-09-05）

**背景**：前身项目 `anime-audio-classification-model` 的设定是「已知目标角色，判断每个片段是不是他」。实际使用中发现，真正想要的是「把一集拆成按人分好的组」，说话人数量和身份事先都不知道。

**决定**：核心算法从说话人验证改为说话人聚类。输出是 $N$ 个分组，$N$ 自动估计。

**理由**：闭集二分类要求为每个目标准备正负样本，换一个角色就要重来一遍，且负类是无穷开放的（新角色、旁白、路人），闭集建模换一集就会大面积误判。

**代价**：主指标从 PR 类指标换成 B-cubed F1；引入「跨集说话人链接」这个没有现成方案、必须自己写的环节；必须设计人工修正（合并/拆分）环节，因为聚类必然出错。

## ADR-002　目标单位是「角色」而非「声优」

**状态**：生效（2026-09-05）

**背景**：同一声优会在同一部作品里分饰多角，也会在不同作品里演不同角色。收集单位可以是「这个角色」也可以是「这个人的声音」。

**决定**：以角色为单位。

**理由**：下游是音色收集，同一声优不同角色的音区与演法差异很大（想想同一人配的少年角色与傲娇少女），混进同一个音色数据集会让音色不自洽。按角色收集得到的才是一个自洽的声音。这不是「更容易」的妥协，而是对目标更正确的建模。

**代价与红利**：跨作品泛化不再是要求，评估划分单位可以降到「按集留出」。同时「信道记忆」不再是威胁 —— 每个角色本来就单独注册，模型学到「这部作品的信道 + 这个角色」无害。唯一要防的是把同作品的其他角色认成目标。

## ADR-003　下游是音色收集，不涉及文本

**状态**：生效（2026-09-05，取代了短暂存在过的 TTS 假设）

**背景**：一度按 TTS 素材设计，包含 ASR 与强制对齐。后确认下游是音色模型（RVC / so-vits-svc 一类），textless。

**决定**：管线中不含 ASR、强制对齐、转写清单、文本规范化、CER 评估。字幕降级为可选的定位线索，字幕语言无关紧要。

**理由**：音色模型不需要文本。保留 ASR 会引入一整条昂贵且容易出错的链路（动画配音的情感化发音对 ASR 是难点），收益为零。

**代价**：无。这一改动纯粹是减法。附带红利是「字幕是中文还是日文」这个待定问题直接作废。

## ADR-004　判别轨与成品轨分离

**状态**：生效（2026-09-05）　**优先级：这是全项目最高的一条红线**

**背景**：说话人嵌入与 diarization 模型都在 16 kHz 上工作，而音色模型多在 40 到 48 kHz 训练。

**决定**：16 kHz 单声道副本**只用于分析**，向下游只传递「时间戳 + 分组 id」。成品音频永远从原始采样率音轨按时间戳直接切。配置项 `export_sample_rate` 默认为 `None`（保持原始），而不是某个具体数值。

**理由**：把降采样后的音频升回去当成品会丢失高频，而且这种损坏**在听感上不明显、在流程中无报错**，属于「报废了也很难察觉」的一类错误。

**代价**：管线要维护两条音频路径，实现复杂度略增。参考实现 Emilia-Pipe 会标准化到 24 kHz、TTSizer 面向 TTS，两者都不能直接照抄导出环节。

## ADR-005　新建仓库，不重构旧仓库

**状态**：生效（2026-09-05）

**背景**：旧仓库 `.git` 有 91 MB（121 MB 的 wav 全进了历史），且代码基于已被推翻的假设。选项是 `git-filter-repo` 改写历史后重构，或另起新仓库。

**决定**：新建 `anime-voice-sorter`，旧仓库保持原状。

**理由**：旧代码没有可复用的部分（特征、模型、评估、输出全部基于二分类假设，见 ADR-001）。既然是重写而非重构，改写公开仓库历史、让已有 fork 与 PR 引用失效就毫无必要。

**代价**：旧仓库的 91 MB 历史仍在，但不再影响新工作。旧代码的问题清单已压缩迁移到 `PRIOR_ART_AUDIT.md`。

## ADR-006　分离的一致性优先于逐条最优

**状态**：生效（2026-09-05，修正了更早的一个错误判断）

**背景**：早期曾判断「BGM 重的片段用分离版，BGM 轻的直接用原音轨，逐条取最优」。

**决定**：选定一条处理路径，全量走完。默认全部走人声分离。

**理由**：两条处理路径混在同一个数据集里，音色模型会学到不一致的伪影特征。数据集内部的一致性比任何单条片段的绝对质量更重要。动画音轨里真正无 BGM 的对白很少，所以默认是全量分离。

**代价**：本可以保留原始保真度的少数干净片段，也要承受一次分离的伪影。manifest 里需记录 `pipeline_hash`，以便成品出问题时定位到是哪一批设置不同。

## ADR-007　分段以 diarization 为准，字幕仅作辅助

**状态**：生效（2026-09-05）

**背景**：字幕时轴免费且现成，直觉上应该直接用它切片，前身项目正是这么做的。

**决定**：diarization 的说话人轮次是分段的主依据。字幕区间只用于**校验**（落在字幕空白处的语音段多半是音效残留，降权或标记），不用于定义边界。无字幕时管线照常工作。

**理由**：字幕有两个致命缺陷。一是**只覆盖台词**，会漏掉惊呼、笑声、喘息这些对音色恰恰很有价值的非台词发声；二是一行常跨两个说话人，边界还有 100 到 300 ms 偏移。

**代价**：必须跑 diarization，比纯字幕切片贵。

## ADR-008　聚类分两层

**状态**：生效（2026-09-05）

**决定**：第一层用 diarization 自带的集内聚类结果；第二层对**每个集内 cluster 的质心**做凝聚层次聚类，实现跨集链接。不把全系列片段丢进一次聚类。

**理由**：cluster 质心是几十秒到几分钟语音的平均，比单个 1.7 秒片段的嵌入稳定得多。同时两层结构把计算量从「片段数的平方」降到「cluster 数的平方」。

**代价**：集内聚类的错误会被带进第二层，需要 review 环节兜底。

## ADR-009　few-shot 标注主要用于阈值标定，命名后置

**状态**：生效（2026-09-05）

**背景**：使用者可能提供少量标注。直觉用途是「事先告诉工具有谁」。

**决定**：不要求使用者预先提供标注。正确顺序是**先聚类，再让使用者给分组命名**。few-shot 是可选加速通道，其首要用途是标定聚类的距离阈值 $\theta$，命名是次要用途。

**理由**：聚类完成后每组只需听 3 到 5 条代表样本就能认出是谁，比事先翻找样本快得多。而 $\theta$ 是整个工具最关键也最难盲选的超参数，每人两三条样本就能把它从「猜」变成「拟合」，这对最终质量的影响大于命名本身。

**代价**：无。这是纯粹的 UX 改进。参考实现 TTSizer 要求在配置里预先写死 `target_speaker_labels`，正是我们要避免的形态。

## ADR-010　主动放弃长尾说话人

**状态**：生效（2026-09-05）

**决定**：设 `min_speaker_duration`（默认 60 s），低于此的分组全部并入 `_misc/`，不试图解析成独立分组。

**理由**：一部动画有 5 到 15 个常驻角色，加上大量只出现一两句的路人。路人的两句话没有收集价值，而试图解析它们会显著抬高聚类难度和人工复核负担。

**代价**：偶尔会误伤台词很少但确实想要的配角。阈值可配置，且 `_misc/` 保留原始片段，可事后捞回。

## ADR-011　torch 按平台绑定 index

**状态**：生效（2026-09-05）

**决定**：`pyproject.toml` 配两个 explicit index，用 `sys_platform` marker 分流：Windows 走 `cu128` 轮子，其他平台走 `cpu` 轮子。torch 与 torchaudio 都钉在 2.11。

**理由**：开发机是 RTX 4060 Laptop 需要 CUDA；CI 在 Linux 上跑，若也拉 CUDA 轮子则每次要下载 2.6 GB。版本钉死是因为首次 lock 时解析出了 torch 2.14 配 torchaudio 2.11 的不兼容组合。

**代价**：升级 torch 时要同时改两处版本约束。

## ADR-012　review 界面优先评估现成工具

**状态**：待验证（2026-09-05）

**背景**：原计划自己写 Gradio 界面。调研发现 `voxmap-studio`（2026，开源）已支持 turn 的 resize / split / delete / reassign，且明确支持跨文件的 global speaker，还有「intrusion 标记」自动高亮最可能标错的段。

**决定**：M4 之前先花半天评估 `voxmap-studio`，能用就不自己写。

**理由**：它的功能覆盖了 M4 的需求，intrusion 标记这个设计还优于原本的构想。能用则省 1 天。

**代价**：论文未给出仓库地址，需先找到代码。若不可用则回退到自写 Gradio，损失半天评估时间。
