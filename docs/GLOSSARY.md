# 术语表

这个项目会碰到一些专业词。这里每个词给一句大白话解释，加上它的英文名（方便你去搜索或查库的文档）。

## 声音处理

**采样率**（sample rate）
录音时每秒记录多少个数据点，单位赫兹。44100 Hz 就是每秒记 44100 个点。数字越大，能记录的高频细节越多，文件也越大。CD 是 44100，很多语音模型用 16000。

**单声道 / 立体声**（mono / stereo）
单声道只有一条音轨，立体声有左右两条。分析声音时通常先把左右混成一条，因为我们关心的是谁在说话，不是声音从哪个方向来。

**人声分离**（source separation）
把一段混合音频拆成「人声」和「伴奏」两部分。动画的音轨里人说话、背景音乐、音效是混在一起的，要先把人声单独抠出来。

**伴奏轨**（stem）
分离之后得到的其中一条，比如「只有背景音乐的那条」。

**静音检测**（VAD，voice activity detection）
自动找出一段音频里哪些地方有人在说话，哪些地方是安静的或只有背景音。

**响度归一**（loudness normalization）
把所有片段的音量调到差不多大，免得有的震耳朵有的听不见。

**削波**（clipping）
音量超过了能记录的上限，波形顶部被切平了。听起来会破音、发糊，而且没法修复。

**伪影**（artifact）
处理之后多出来的、原本不存在的怪声音。人声分离最常见的伪影是金属感、水声、忽大忽小的杂音。

**混响**（reverberation）
声音在空间里反射产生的回音。在大厅里说话和在小房间里说话，混响差别很大。

**重叠语音**（overlapped speech）
两个人同时在说话。这种片段对我们没用，因为分不清是谁的声音。

**分离质量分**（SDR，signal-to-distortion ratio）
衡量人声分离做得好不好的分数，单位分贝，越大表示抠出来的人声越接近原本干净的人声。要注意它几乎都是在音乐上测的（唱歌配伴奏），换成动画对白配背景音乐和音效，名次不一定还成立。

**串音**（bleed）
该被去掉的声音漏进了结果里，比如抠完人声之后还能听见背景音乐。模型名字里的 `bleedless` 就是「少串音」，这类模型宁可把人声削掉一点，也不让伴奏漏过来。

## 说话人识别

**音色**（timbre）
一个人声音的独特质感。同样唱一个音高，不同人听起来不一样，差别就在音色。

**说话人分段**（speaker diarization）
把一段音频切开，标出每一段是谁在说。注意它**不知道这些人叫什么名字**，只会给编号，比如「说话人 0」「说话人 1」。而且这些编号**只在这一次处理里有效**，换一集重新跑，编号会重新分配，跟上一集对不上。

**声音指纹**（speaker embedding）
把一段声音变成一串数字（通常一两百个数）。设计目标是：同一个人的两段声音，得到的数字会很接近；不同人的会差很远。有了它，比较两段声音像不像，就变成了比较两串数字像不像。

**余弦相似度**（cosine similarity）
比较两串数字有多像的一种算法，结果在 -1 到 1 之间，越接近 1 越像。

**中心点**（centroid）
一组声音指纹的平均值，代表这一组的「中心」。比如把某个角色的一百段声音指纹平均一下，就得到这个角色的中心点。

**聚类**（clustering）
在不知道有几个人、也不知道他们是谁的情况下，把像的归到一起、不像的分开。这跟「分类」不一样：分类是事先就知道有哪几类，聚类是自己找出来有几类。

**层次聚类**（hierarchical clustering）
一种聚类的做法：一开始每段声音各自成一组，然后反复把最像的两组合并，直到剩下的组之间都不够像为止。

**阈值**（threshold）
一个分界线数值。比如「相似度超过 0.7 就算同一个人」，0.7 就是阈值。这个数字定得太高会把一个人拆成好几组，定得太低会把不同人并成一组。

**只给几个例子**（few-shot）
使用者不做大量标注，只提供每人两三条样本。

**开放集合**（open-set）
要找的人不是固定几个，随时可能冒出没见过的新角色、旁白、路人。跟它相对的是「封闭集合」，即事先就知道总共只有这么几个人。

## 质量与评分

**音质分**（DNSMOS）
一个模型给音频打的质量分。它给三个分数：BAK 分低说明背景杂音大，SIG 分低说明人声本身被处理坏了，OVRL 是综合分。我们主要看 BAK（有没有残留背景音乐）和 SIG（有没有分离伪影）。

**声纹错误率**（EER，equal error rate，等错误率）
衡量声音指纹好不好的分数，百分比，越小越好。做法是调一个分界线，让「把不同人判成同一个人」和「把同一个人判成不同人」这两种错的比例相等，那个相等的值就是它。

**分段错误率**（DER，diarization error rate）
衡量说话人分段做得好不好的分数，百分比，越小越好。它把三种错误加在一起算：该说话的时候判成没人说、没人说的时候判成有人说、说话人认错。

**分组好坏分**（B-cubed F1）
衡量聚类结果好不好的分数。它同时惩罚两种错误：该分开的合到了一起、该合到一起的却分开了。所以它比单看「对了多少条」更能反映聚类的真实水平。

**纯度**（purity）
某个分组里，真正属于这个人的片段占多大比例。这是使用者最关心的数字：如果 `speaker_01/` 里有 95% 真的是同一个人，那就基本能用。

**开一次关一次做对比**（ablation，消融实验）
想知道某个步骤有没有用，就开着它跑一遍、关掉再跑一遍，比较结果差多少。

## 工程

**uv**
一个 Python 项目和依赖管理工具，比 pip 快很多。`uv sync` 会按照锁文件把环境装成一模一样。

**锁文件**（lock file，本项目是 `uv.lock`）
记录每个依赖包的确切版本。有了它，换一台机器装出来的环境跟你这台完全一致。

**CI**（continuous integration，持续集成）
代码推到仓库后自动跑一遍检查（格式、类型、测试）。防止「在我机器上是好的」。

**parquet**
一种存表格的文件格式，比 CSV 小很多也快很多，而且能记住每一列是什么类型。

**需要先点同意的模型**（gated model）
有些模型在下载前要求你先去它的网页上接受使用条款，然后用账号令牌（token）才能下载。本项目用的说话人分段模型就是这样。

**决策记录**
把「当时为什么这么选」写下来的文档。业界常叫 ADR（architecture decision record），本项目的 `DECISIONS.md` 就是这个东西，只是不用那个缩写。
