# 流程、数据和名词

## 名词表

这个项目以前用过一批省字的简称（错合、漏合、干扰项之类）。现在一律不用，改成下面这些说法。读旧提交信息时可能还会碰到旧词，对照这张表看。

| 现在的说法 | 意思 |
| --- | --- |
| 错误合并 | 两条属于不同角色的片段被放进了同一组 |
| 该合没合 | 两条属于同一角色的片段落在不同组。音频没丢，只是没归到一起 |
| 同一角色的配对 / 不同角色的配对 | 从有人工名字的片段里两两取对，按两条是不是同一个角色分成两类 |
| 连上的比例 | 同一角色的配对中，被放进同一组的占多少 |
| 陪衬片段 | 留在候选池里当背景、但自己不作为提问对象的片段 |
| 没有分到组 | 这条片段没有声纹（太短），因此不参与分组 |
| 声纹 | 把一段声音变成一组数，用来比较是不是同一个人的声音 |
| 距离 | 两条声纹之间的余弦距离。0 表示方向完全一致，越大越不像。它不是「是同一个人的概率」 |
| 距离分界线 | 距离小于它才允许把两条片段连起来。命令行里的参数名是 `--threshold` |
| 片段池 | 这一次分组把哪些片段放在一起比。三集一起分组时，池子就是这三集的全部片段 |
| 按池子定分界线 | 分界线不写死一个数，而是由这个池子自己的距离算出来：全部配对距离由近到远排开，取第 1% 那个距离，再乘一个固定倍数。命令行里是 `avs group --relative` |
| 按整组平均距离合并 | 层次聚类的一种合并规则：两组之间所有片段的平均距离达标才合并。命令行里叫 `average` |
| 排序正确率 | 随机拿一对同一角色的片段和一对不同角色的片段，同一角色那对距离更近的比例。完全随机是 0.50，完美是 1.00 |
| 相等错误率 | 把分界线挪到「同一角色被错误分开」和「不同角色被错误合并」这两种错误一样多的位置，那时候的错误率。越小越好 |
| 独立检验 | 在一份完全没参与过调参的数据上重新打分。同一批标签既调参又打分，看不出问题 |

## 一条路线，五步

1. **`prepare`**：分离整集人声，保持原采样率；再把字幕加上这一集的偏移秒数，**每条字幕行就是一个片段**。

   语音检测只用来量这个偏移是多少秒，不参与判断片段里有没有人在说话。给了 `--offset` 就完全不跑检测。对齐吻合度太低会直接报错，不会悄悄换成别的做法。

2. **`embed`**：把不短于 0.5 秒的片段算成单位长度的声纹向量。更短的片段留在片段表里，但没有声纹，因此进不了分组。缓存跟片段文件内容、分析音频内容、模型名和时长下限绑在一起，其中任何一项变了都必须重算。

3. **`group`**：全部集的片段一起直接按声纹分组，不先把每集压成一个中心点。默认模型 `anime-va`、按整组平均距离合并、距离分界线 0.70。**每个模型有自己的默认分界线**，不同模型的相似度刻度不一样，照搬会扫在毫无意义的一段上。小组保留，不会被并进一个杂物组。

4. **`evaluate`**：只用人工身份归档打分，音轨相同、起止时间毫秒级完全一致才参与。报错误合并数、该合没合数、没对上的标签、没有分到组的片段，以及每个角色散在几个组里。

5. **`export`**：按分组从原采样率人声轨切 WAV，没有分到组的另存一处。响度统一但不削顶。

音质不是当前的准入条件。「一条片段里只有一个人说话」是工作假设，不是检测结论。

辅助命令：`coverage` 核对字幕里有没有台词没被切出片段；`extend` 把这类台词补进片段表（只增不改，已有标签不受影响）；`scores` 只比较分得开不开，不做分组；`compare` 扫分界线；`drift` 量成绩随片段池变大怎么变；`diagnose` 做近邻检索和距离分布；`label` 开标注页；`label-plan` 划定一轮标注的范围。命令见[根 README](../README.md)。

## 打分怎么读

- 「同一角色的配对」总数这样算：某个角色有 n 条带名字的片段，就有 n(n−1)/2 对，再把所有角色加起来。不是把全部标签不分角色算组合数。
- 举例：某角色有 A、B、C 三条，A 和 B 同组、C 单独一组。同一角色的配对共 3 对，连上 1 对，该合没合 2 对。只报「错误合并为零」会把这个问题藏起来。
- **只报错误合并为零没有意义**：每条片段各自成组也能做到零错误合并。必须同时看该合没合、组数，以及有多少片段还没有人工名字。
- 没有分到组的片段各自算独立一组参与打分。没有人工名字的片段不能当成「里面没混进别的角色」。
- 报告里的 `adjusted_rand` 是个综合分，不能替代错误合并和该合没合这两个具体数。
- 给算法提供身份的参考片段必须从打分中排除，对照的基线也要排除同一批片段。已经用来试过方法的剩余标签仍然不算独立检验。

## 目录

```text
src/avs/
  cli.py                   命令入口
  project.py               一集与片段的数据契约、内容指纹、缓存目录
  pipeline.py              准备、补片段、声纹缓存、分组、导出的编排
  audio.py                 分离人声、做分析副本、量字幕偏移所用的说话时间线
  embeddings/extract.py    四个声纹模型与时长下限
  stages/subtitle.py       读字幕、量偏移
  stages/cluster.py        全局声纹分组与几种合并规则
  stages/normalize.py      分数归一化（已证明无效，留作依据）
  stages/export.py         原采样率导出
  evaluation/identity.py   身份打分
  evaluation/compare.py    同片段同标签下扫模型与分界线
  evaluation/drift.py      量成绩随片段池变大怎么变，对比两种定分界线的做法
  evaluation/coverage.py   对白覆盖核对，切出没被覆盖的台词
  evaluation/scores.py     排序正确率与相等错误率，按时长和跨集分层
  evaluation/references.py 少量身份参考实验（已关闭，留作依据）
  evaluation/diagnose.py   近邻检索、距离分布、错误实例
  labeling.py              安排标注范围、切音频和视频、保存人工归档
  label_page.py            标注页面
```

每集 `episode.json` 记素材与音轨路径，`segments.json` 记片段 ID、集名、起止时间。声纹放在 `embeddings/<模型名>/`，用别的最小音频长度算出来的放在 `embeddings/<模型名>@w<秒数>/`，矩阵与元信息按行对应。改了片段之后旧缓存会报错，不会被悄悄用上。

**片段 ID 是集名加起止时间的哈希，跟邻居无关。** 所以往片段表里只增不改能保住已有标签；重切就没有这个便宜可占，标签会全部作废。

`groups.json` 自带各集音轨位置和每条片段的归属，`speaker=null` 表示没有分到组。路径是绝对路径，搬项目要更新音轨位置；片段 ID 不因目录移动或重新分组而改变。

对照实验不要同时改片段边界。引入身份参考时必须区分「提供身份的片段」和「用来打分的片段」。
