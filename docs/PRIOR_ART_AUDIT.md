# 前身项目审计

> 状态：**冻结**。本文档只记录前身项目 `anime-audio-classification-model` 错在哪里，作为「不要再犯」的清单。
> 它不包含本项目的任何内容，也不应再更新。

前身项目的设定是「已知目标角色（某位声优的角色），判断每个字幕切片是不是他」，用 MFCC 均值向量加 SVM 做二分类。为什么完全不复用它，见 [`DECISIONS.md`](DECISIONS.md) 的 ADR-001 与 ADR-005。

## 数据规模（实测）

| 项目 | 数值 |
| --- | --- |
| 代码 | 5 个 `.py`，约 620 行，其中一个文件名含中文（`a002_网络基类.py`） |
| 训练数据 | 目标类 95 条、其他类 215 条 |
| 测试数据 | 24 条，**无标签** |
| 音频规格 | 全部 44100 Hz / 立体声 / 16-bit PCM |
| 时长 | 目标类 294 s（中位 2.80 s），其他类 420 s（中位 1.71 s），共约 12 分钟 |
| 仓库体积 | 工作区 141 MB，`.git` 91 MB（wav 全部进了 git 历史） |

## A. 会直接报错或导致错误结果的 bug

| 位置 | 问题 | 后果 |
| --- | --- | --- |
| `a002_网络基类.py` 类属性 | `save_model_per_epochs = SAVE_MODEL_FOLDER`（应为 `SAVE_MODEL_PER_EPOCHS`） | `current_epoch % "./saved_model"` 抛 `TypeError`，ANN 训练路径**实际从未跑通** |
| `a002_网络基类.py` `initialize_nn()` | 先对**全量数据**做 z-score，再 `random_split` | 验证集统计量泄漏进训练，验证准确率虚高。文件顶部 TODO 自己也写了这一条却没修 |
| `a001_preprocess.py` `unify_dim_t()` | 样本比 `dim_t` 长时 `zeros_length` 为负 | `torch.zeros(..., -n)` 抛 `RuntimeError`，且没有截断分支 |
| `a002_ANN.py` `__main__` | 函数体只有 `pass` | ANN 没有入口，README 承诺的三个模型只有 SVM 可用 |
| `a001_preprocess.py` `load_wav_data()` | `os.listdir` 不过滤扩展名 | 目录下任何非音频文件都会让 `torchaudio.load` 崩 |
| `a002_SVM.py` `output_prediction()` | 对配置里的 `RESULT_FOLDER` 无条件 `shutil.rmtree` | 配错一次路径就是不可逆删除 |
| `requirements.txt` | UTF-16 编码；`sklearn==0.0.post4` 是废弃占位包，安装即报错；`torch~=2.0.0+cu118` 带 local version，PyPI 解析不到；混入教程遗留的 `mnist` | 依赖装不上 |

**教训**：本项目用 ruff + mypy strict + pytest + CI 拦截这一类问题；配置用 pydantic 做类型校验，让 `save_model_per_epochs = <path>` 这种赋值在启动时就报错；防泄漏靠把归一化放进 `sklearn.pipeline.Pipeline` 这种结构性手段，而不是靠人记得顺序；任何删除操作要求目标目录为空或显式 `--force`。

## B. 工程规范问题

1. **配置即全局变量 + `import *`**：无法在一次进程里跑两组参数，无法做超参搜索，IDE 无法追踪来源。
2. **中文文件名与目录名**：在 CI、Docker、非 UTF-8 locale 下都是雷区。
3. **`a00x_` 前缀假装依赖顺序**：脚本思维，不是模块划分。根目录一个空 `__init__.py` 但没有任何包。
4. **状态挂在类属性上**：`MyNN` 把 `criterion`、`optimizer`、三个 dataloader 定义成类变量，多实例互相污染。
5. **硬编码 `MY_DEVICE = 'cuda'`**，且在数据函数里调用 `torch.set_default_device()` 这种全局副作用。
6. **模型不可持久化**：SVM 的 `model`、`mean`、`std` 全在内存，训练与推理必须同进程跑完，换一集还得重训。
7. 无日志（全 `print`）、无随机种子、无 CLI、无类型标注、无测试、无 CI。
8. **数据进了 git**：121 MB wav 让 clone 变成 91 MB 下载，连 `分类结果/` 这种程序输出也被提交。

## C. 方法论问题（最致命的一层）

1. **特征选择过时**：MFCC 沿时间轴取均值成 40 维向量，丢掉基频轨迹与韵律，而这些才是说话人身份的主要载体。起点应该是预训练说话人嵌入。
2. **没有任何音频前处理**：44.1 kHz 立体声直接进 MFCC，没重采样、没单声道下混、没响度归一、没 VAD。字幕切片前后必然带静音，还叠着 BGM 和音效。**动画音轨的 BGM 是最大噪声源，流程里完全没处理。**
3. **指标不可信**：
   - 按片段随机划分，但所有片段来自同一集。相邻台词共享同一场景的混响、BGM、编码，模型可以靠「信道指纹」而非「音色」拿分。
   - 类别不平衡 215 : 95（69% / 31%），却只报 accuracy。全预测为负类就有 69%。
   - 验证集只有约 62 条，单次划分，无交叉验证、无固定种子，两次运行的数字不可比。
   - 测试集没有标签，**整个项目从头到尾没有一个诚实的泛化指标**。
4. **问题被建模错了**：真实需求是开集问题（非目标类是无穷开放的：新角色、旁白、路人），却建模成闭集二分类，换一集就会大面积误判。
5. **数据量与模型容量不匹配**：250 条训练样本配 6 层 MLP、`lr=0.01`、`TOTAL_EPOCHS = 100000`，没有早停、没有学习率调度、没有类别权重。

**教训**：本项目的评估设计（[`DESIGN.md`](DESIGN.md) 第 6 节）从一开始就要求诚实的划分单位与贴合用途的指标；前处理（分离、VAD、重采样）在管线里有明确位置；建模方式改为聚类（ADR-001）。
