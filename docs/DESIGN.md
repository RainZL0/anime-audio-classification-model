# anime-voice-sorter 设计文档

> 版本：v4（推翻重来的全新设计）　　日期：2026-09-05
> 旧代码审计见 `REFACTOR_PLAN.v1.md`，仅作「不要再犯」的记录，代码本身不保留

## 1. 工具定位

一句话：**把一部动画拆成按人分好组的纯净人声片段，供音色收集使用。**

输入输出契约：

```
输入：  一部动画的若干集（视频或音轨）+ 对应字幕（可选）
       可选：使用者提供的少量标注（每人几条样本）

输出：  out/
        ├─ speaker_01/  *.wav        原始采样率、无 BGM、单人、无重叠
        ├─ speaker_02/  *.wav
        ├─ _misc/       *.wav        时长不足以单独成组的零散说话人
        ├─ _rejected/                被质量闸门拒收的片段（保留以便复查）
        └─ manifest.parquet          每个片段的完整元数据与判决理由
```

若使用者提供了标注，输出目录名换成人名（`taiga/`、`ryuuji/`），未匹配上的仍用 `speaker_NN`。

**关键定位判断**：这是一个**聚类**工具，不是分类工具。说话人数量未知、身份未知，使用者事后才告诉你谁是谁（甚至不告诉）。这一条决定了后面所有技术选择。

## 2. 为什么旧代码全部作废

旧代码建立在「目标角色已知、有充足正负样本、二分类」这三个前提上，新目标一个都不成立：

| 旧前提 | 新现实 |
| --- | --- |
| 目标角色已知 | 说话人未知，数量也未知 |
| 有标注的正负样本 | 可能零标注，或每人只有几条 |
| 输出是二分类结果 | 输出是 $N$ 个分组，$N$ 需要自动估计 |
| MFCC 均值 + SVM | 需要能做聚类的强判别嵌入 |
| 逐片段独立判决 | 需要跨集把同一个人的分组连起来 |

所以这是重写，不是重构。仓库名也应改为 `anime-voice-sorter`（旧名 `anime-audio-classification-model` 已经描述错了这个工具）。

## 3. 端到端管线

```
                    ┌──────────────────────────────────────────┐
输入：视频 + 字幕   │  原始音轨（保持 44.1/48 kHz，永不丢弃）  │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
              1.    │ separate  人声分离（Mel-Band Roformer）  │  ← 缓存
                    └──────────────────┬───────────────────────┘
                                       │
              ┌────────────────────────┴────────────────────────┐
              │ 判别轨（16 kHz mono 临时副本）                   │
              │                                                 │
     2.  ┌────▼─────────┐   3.  ┌──────────────┐                │
         │ diarize      │       │ subtitles    │                │
         │ 说话人轮次   │  ×    │ 台词时轴     │  → 候选片段     │
         │ + 重叠标记   │       │（可选先验）  │                │
         └────┬─────────┘       └──────────────┘                │
              │                                                 │
     4.  ┌────▼─────────┐                                       │
         │ embed        │  每个片段一个说话人嵌入               │  ← 缓存
         └────┬─────────┘                                       │
              │                                                 │
     5.  ┌────▼──────────────────────────────────────┐          │
         │ cluster                                    │          │
         │  a) 集内聚类（diarization 已给）           │          │
         │  b) 跨集链接：对集内 cluster 质心再聚类    │          │
         │  c) 估计说话人数量（阈值 / eigengap）      │          │
         └────┬───────────────────────────────────────┘          │
              │                                                 │
     6.  ┌────▼─────────┐  ← few-shot 标注在此介入（三种用法）   │
         │ assign/name  │                                       │
         └────┬─────────┘                                       │
              └─────────────────────┬───────────────────────────┘
                                    │  只传递「时间戳 + 分组 id」
                    ┌───────────────▼──────────────────────────┐
     7.             │ review   人工听样本，命名 / 合并 / 拆分  │
                    └───────────────┬──────────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────────┐
     8.             │ quality  重叠 / DNSMOS / 时长 / 削波闸门 │
                    └───────────────┬──────────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────────┐
     9.             │ export   从原始采样率音轨按时间戳切片    │
                    └──────────────────────────────────────────┘
```

**贯穿全流程的红线**：判别轨（16 kHz 单声道）只用于分析，向下游传递的只有**时间戳与分组 id**。音频本体永远从原始采样率的音轨走，绝不从降采样副本升回去。音色模型多在 40 到 48 kHz 训练，这条搞错会让成品静默报废。

## 4. 数据模型

全流程围绕**一张逐阶段增列的表**，`data/<show>/segments.parquet`：

| 列 | 产生阶段 | 说明 |
| --- | --- | --- |
| `seg_id` | segment | 主键 |
| `episode`, `start`, `end` | segment | 相对原始音轨的时间戳 |
| `source` | segment | `sub` / `diar` / `both`，记录这一段的来源 |
| `overlap` | diarize | 是否与其他说话人重叠 |
| `local_cluster` | diarize | 集内说话人 id |
| `emb_path` | embed | 嵌入缓存位置 |
| `global_speaker` | cluster | 跨集链接后的全局分组 |
| `assigned_name` | assign/review | 使用者给的名字，可为空 |
| `dnsmos_bak`, `dnsmos_sig` | quality | 背景干扰、语音失真 |
| `duration`, `clip_rate`, `lufs` | quality | 基础音频指标 |
| `decision`, `reject_reason` | quality | `accept` / `uncertain` / `reject` |
| `pipeline_hash` | 全程 | 处理路径标识，见 6.9 |

好处：每个阶段是纯函数（读表、加列、写表），可单独重跑，可断点续跑，可直接用 pandas 检查。聚类和 review 会被反复迭代，而分离与嵌入只算一次，这个结构让重跑成本正确地落在便宜的那几步上。

## 5. 各阶段设计

### 5.1 ingest：双轨

抽音轨用 `ffmpeg`，**不做任何重采样**。同时生成一份 16 kHz 单声道副本供分析用，标记为临时文件。

### 5.2 separate：人声分离

**Mel-Band Roformer** 的人声检查点，经 `python-audio-separator` 调用。Mel-Band 相对 BS-Roformer 在两种深度上分别再拿到 0.43 dB 与 0.58 dB。UVR5 的 GUI 已停在 v5.6.x，只用于人工试听比较检查点，不进流水线。

分离结果同时供判别与成品使用，**全量走同一条路径**。不要「BGM 重的用分离版、BGM 轻的用原版」，两条处理路径混在一个数据集里会让音色模型学到不一致的伪影。一致性优先于逐条最优。

去混响默认关闭。场景混响确实会被音色模型学进去，但去混响本身也引入伪影，需要 A/B 听感对比后才决定是否纳入。

### 5.3 segment：字幕 × diarization

这是新设计里第一个需要想清楚的地方。两个信息源各有各的问题：

| | 字幕时轴 | diarization |
| --- | --- | --- |
| 覆盖 | 只有台词，漏掉惊呼、笑声、喘息等**对音色很有价值的非台词发声** | 全覆盖 |
| 边界 | 常有 100 到 300 ms 偏移，且一行可能跨两个说话人 | 贴合实际语音 |
| 说话人 | 无 | 有（集内） |
| 重叠 | 无 | 有 |
| 成本 | 免费 | 需要推理 |

**结论：以 diarization 为准，字幕作为辅助先验。** 具体做法是求交与互补：

- diarization 给出的说话人轮次是分段的主依据。
- 字幕区间用于**校验**：某段 diarization 轮次若完全落在字幕空白处，多半是背景杂音或音效残留，降权或标记。
- 字幕**不用于**定义边界，避免把偏移和跨说话人的行带进来。
- 没有字幕时管线照常工作，字幕是可选输入。

`source` 列记录每段的来源，方便事后分析两者的贡献。

### 5.4 diarize

`pyannote/speaker-diarization-community-1`。相对 3.1，分割性能（VAD 与重叠检测）持平，改进在说话人指派与计数，说话人混淆明显下降，另有 exclusive single-speaker 模式可用于消除重叠冲突。**必须先分离人声再 diarize，顺序不能反。** 它在 HF 上是 gated，需要接受条款。

NeMo Sortformer 每段最多 4 说话人，动画场景不适用，排除。

要清醒的一点：那些公开 DER 数字来自会议、播客、广播域。经验规律是干净双人录音的说话人归属正确率能到 95% 以上，三人以上带重叠会掉到 75% 到 85%。动画一集常有 5 到 10 个角色，落在后一档。所以 diarization 的输出是**待修正的草稿**，不是终判，第 5.7 节的人工修正环节是设计的一部分而非补丁。

### 5.5 embed

`ReDimNet-B2` 与 `WeSpeaker ResNet34` 双跑，按你自己数据上的表现选。VoxCeleb1-O 已接近饱和（SOTA 报到约 0.17% EER），模型在真人朗读语音上的排序，到日语动画配音这个域完全可能颠倒。备选 ECAPA2、CAM++ / ERes2NetV2。

按 `(model_id, audio_sha256, start, end)` 做磁盘缓存。

短片段的嵌入不可靠，`duration < 1.0 s` 的段参与不了聚类决策，只在归组后被动跟随所在轮次。

### 5.6 cluster：本工具的算法核心

分两层，因为直接把全系列所有片段丢进一次聚类既慢又差。

**第一层，集内**：diarization 自带的聚类结果直接用。

**第二层，跨集链接**：这是 pyannote 不提供、必须自己做的部分。

1. 每个集内 cluster 取其片段嵌入的均值（长度加权），得到一个 cluster 质心。质心是几十秒到几分钟语音的平均，比单个 1.7 秒片段稳得多，这是分两层的主要理由。
2. 对全系列所有质心做凝聚层次聚类（AHC，余弦距离，average linkage）。
3. 用**距离阈值**而非固定 $k$ 来切树，因为说话人数量未知。

阈值 $\theta$ 是整个工具最关键的超参数，也是最难盲选的。三种定法，按可得性排序：

- **有 few-shot 标注**：直接用标注算类内与类间距离分布，取使 B-cubed F1 最大的 $\theta$。这是 few-shot 最有价值的用途，见 5.7。
- **无标注但要自动**：用 eigengap 或轮廓系数扫一遍 $\theta$，取拐点。
- **兜底**：给一个经过标定的默认值，并在 review 阶段暴露一个滑块让使用者实时看分组数变化。

**长尾处理**：一部动画有 5 到 15 个常驻角色，加上大量只出现一两句的路人。不要试图把每个路人都解析成独立分组。设一个 `min_speaker_duration`（默认建议 60 s），低于此的分组全部并入 `_misc/`。这既符合「收集音色」的实际用途（路人的两句话没有收集价值），也大幅降低了聚类难度和 review 负担。

### 5.7 few-shot 标注的三种用法

按价值排序，第一条最重要且最容易被忽略：

1. **标定聚类阈值。** 只要每人两三条样本，就能把 $\theta$ 从「盲猜」变成「拟合」。这对最终质量的影响大于命名本身。
2. **给分组命名。** 用标注样本的质心与各全局分组质心比余弦，最近且超过阈值的分组获得该名字，其余保留 `speaker_NN`。
3. **约束聚类**（可选，复杂度高）。把同名样本作为 must-link、异名作为 cannot-link 注入 AHC。收益相对前两条小，列为后续增强。

**但更重要的一个 UX 判断**：不要要求使用者**预先**提供标注。正确顺序是**先聚类，再让使用者给分组命名**，因为聚类完成后每个分组只需听 3 到 5 条代表样本就能认出是谁，比事先翻找样本快得多。few-shot 模式应该是可选加速通道，不是必经之路。

代表样本的挑选：取距离质心最近的若干条，同时保证时长和场景有一定分散，避免全挑同一场戏。

### 5.8 review：合并与拆分是核心功能

diarization 与聚类必然出错，而且错法是**系统性**的，不是随机的。设计必须假定使用者要修正：

| 错误类型 | 成因 | 修正操作 |
| --- | --- | --- |
| 同一角色被拆成多组 | 音区差异大（平静 vs 吼叫）、有变声处理（电话、机械音）、幼年与成年版本 | **合并** |
| 不同角色被并成一组 | 同一声优分饰多角、音色确实相近 | **拆分** |
| 歌声独立成组 | 插入曲、角色歌，人声分离会保留 | 标记丢弃或单独归档 |
| 旁白独立成组 | 信道不同（干声、无环境音） | 通常是正确行为，命名即可 |

所以 review 不是「看看结果」，而是一个必须做得顺手的编辑器：听代表样本、命名、拖动合并、按嵌入距离拆分、调阈值实时预览。**最小实现是一个 Gradio 页面**，成本不高，但它决定了这个工具好不好用。

### 5.9 quality：闸门

按重要性排序：

1. **重叠语音 → 拒收。** 音色数据集对重叠零容忍，也是最难事后排查的污染。
2. **DNSMOS BAK 过低 → 拒收。** BAK 分量直接度量背景干扰强度，是检测 BGM 残留的正确工具。
3. **DNSMOS SIG 过低 → 拒收。** 捕捉分离伪影。
4. 时长不在 $[1.0, 12.0]$ s → 拒收或切分。
5. 削波率、DC offset、响度离群 → 拒收。

阈值不要凭直觉写死，用首次运行得到的分布加人工听感标定。可用 `torchaudio.pipelines.SQUIM_OBJECTIVE` 做交叉验证。

被拒片段进 `_rejected/` 并记录 `reject_reason`，不直接删除，方便发现闸门设错。

### 5.10 export

从**原始采样率**音轨按时间戳切片，首尾各留约 50 ms padding，统一响度归一但避免削波。

`pipeline_hash` 记录这一批用的分离检查点、是否去混响、闸门阈值等，写进 manifest。当成品出现音色不一致时，这一列让你能定位到是哪一批设置不同，这在混用过多次设置之后是唯一能救命的东西。

## 6. 已知失败模式

这一节比选型更重要，因为这些是设计必须容纳而不是消灭的东西。

| 失败模式 | 严重度 | 应对 |
| --- | --- | --- |
| 一个声优在同作品分饰多角 | 高，且自动方法无解 | 只能靠 review 拆分；文档里明确说明 |
| 同一角色多种声线（变身、附身、幼年） | 高 | review 合并；可在 UI 提示「这两组距离很近」 |
| 重叠语音 | 高 | diarization 重叠检测强制拒收 |
| 歌唱段落 | 中 | 检测伴奏 stem 能量，高能量区间的人声标记为疑似歌唱 |
| 非台词发声（惊呼、笑、喘） | 中，且**对音色有价值不该丢** | 依赖 diarization 而非字幕分段，正是为此 |
| 电话 / 广播 / 机械音滤镜 | 中 | 会自成一组，review 时决定合并还是单独保留 |
| 人声分离伪影 | 中 | DNSMOS SIG 闸门；必要时换检查点或做 ensemble |
| 集数少时跨集链接不稳 | 中 | 质心层聚类已缓解；集数 < 3 时提示结果不可靠 |
| 预训练嵌入的域偏移（真人语音 → 动画配音） | 未知，需实测 | 双模型对比；必要时用伪标签做域适配微调 |

## 7. 评估

工具的评估要贴合用途，不要套 DER 这种需要昂贵参考标注的指标。

**低成本协议**：在一部动画里随机抽约 200 个片段人工标注说话人，然后算：

- **B-cubed F1**：对每个片段 $e$，精确率是其所在分组中与 $e$ 同真实身份的比例，召回率是同真实身份的片段中落在 $e$ 所在分组的比例，两者对全体取平均后求调和平均。它同时惩罚过度合并与过度拆分，是聚类场景的正确主指标。
- **各分组纯度**：导出的 `speaker_NN/` 里真正属于该人的比例。这是使用者真正关心的数字。
- **产量**：每个主要角色导出的净时长。音色收集通常 10 到 30 分钟就够，够了就不必再优化召回。

你仓库里现有的 95 + 215 条标注片段可以立刻当作一个迷你评估集，不用等新标注。

**不追求**的指标：accuracy（无意义）、DER（成本过高且与用途脱节）。

## 8. CLI 与仓库结构

每个子命令对应一个阶段，读写同一张表，可单独重跑：

```bash
avs ingest    --show toradora --video "ep*.mkv" --subs "ep*.ass"
avs separate  --show toradora
avs diarize   --show toradora
avs embed     --show toradora --model redimnet-b2
avs cluster   --show toradora [--enroll labels/]     # few-shot 可选
avs review    --show toradora                        # 打开 Gradio
avs export    --show toradora -o out/
avs run       --show toradora                        # 一条龙
```

```
anime-voice-sorter/
├─ pyproject.toml            # uv，Python 3.12，ruff/mypy/pytest 配置集中
├─ uv.lock
├─ configs/default.yaml
├─ src/avs/
│  ├─ config.py              # pydantic-settings
│  ├─ table.py               # segments.parquet 的读写与 schema 校验
│  ├─ stages/
│  │  ├─ ingest.py  separate.py  diarize.py  segment.py
│  │  ├─ embed.py   cluster.py   assign.py
│  │  └─ quality.py export.py
│  ├─ embeddings/            # Embedder Protocol + 各实现 + 缓存
│  ├─ review/app.py          # Gradio
│  ├─ evaluation/            # B-cubed、纯度、产量
│  └─ cli.py                 # typer
├─ data/<show>/              # .gitignore
├─ tests/fixtures/           # 几条 <1MB 短样本，供 CI
└─ .github/workflows/ci.yml
```

工程规范沿用之前定的：uv + `pyproject.toml`、`src/` 布局、pydantic-settings 取代全局常量、typer、`logging` 取代 `print`、ruff + mypy + pytest + CI、数据不进 git、文件名全 ASCII。

| --- | --- | --- | --- |
| **M0** | 仓库治理：`git-filter-repo` 剥离 91 MB wav 历史、`.gitignore`、ASCII 化、改名 | 0.5 天 | clone < 5 MB |
| **M1** | 工程骨架：uv、包结构、config、CLI 骨架、`table.py`、CI 全绿 | 1 天 | `avs --help` 可用，三绿 |
| **M2** | **纵向打通**：ingest → separate → diarize → embed → cluster → export，先不做 review 和质量闸门，单集跑通 | 1.5 天 | 一集动画产出按人分组的目录，人工听着大致对 |
| **M3** | 跨集链接 + 阈值标定 + 长尾归并 | 1 天 | 全系列产出稳定分组，B-cubed F1 有数字 |
| **M4** | review 界面（命名 / 合并 / 拆分 / 阈值滑块） | 1.5 天 | 修正一部动画的分组耗时 < 15 分钟 |
| **M5** | 质量闸门 + 双轨导出 + manifest 完整化 | 1 天 | 成品无重叠、无 BGM 残留、原始采样率 |
| **M6** | few-shot 通道、评估脚本、README、打包 | 1 天 | 他人可用 |

**M2 优先于一切。** 先把最薄的一条纵向路径打通，比把任何单个环节做完美都重要，因为现在还不知道 diarization 在动画上到底能做到什么水平，那个数字会反过来决定 M3 到 M5 各投入多少。

## 10. 待定问题

1. **git 历史**：`filter-repo` 加强推会改写所有 commit hash，公开仓库已有的 fork 与 PR 引用会失效。接受则重写，不接受则新建仓库、旧仓库归档只读。**需要你定。**
2. **使用者范围**：只给自己用，还是打算让别人也能装来用？这决定 M6 投入多少（打包、文档、错误提示、模型自动下载）。当前按「自己先用，之后可分享」的默认来设计。
3. **作用域粒度**：当前设计以「一部动画」为单位做跨集链接。是否需要跨作品的说话人库（同一声优在不同作品间关联）？这是另一个量级的问题，建议明确排除在 v1 之外。
