# 设计

> 本文档管**管线结构、数据模型、各阶段要解决什么问题、失败模式、评估方法**。
> 具体用哪个库和模型见 [`TOOLING.md`](TOOLING.md)。进度见 [`ROADMAP.md`](ROADMAP.md)。取舍理由见 [`DECISIONS.md`](DECISIONS.md)。

## 1. 工具定位

**把一部动画拆成按人分好组的纯净人声片段，供音色收集使用。**

```
输入：  一部动画的若干集（视频或音轨）+ 对应字幕（可选）
       可选：使用者提供的少量标注（每人几条样本）

输出：  out/
        ├─ speaker_01/  *.wav        原始采样率、无 BGM、单人、无重叠
        ├─ speaker_02/  *.wav
        ├─ _misc/       *.wav        时长不足以单独成组的零散说话人
        ├─ _rejected/                被质量闸门拒收的片段（保留以便复查）
        └─ manifest.parquet          每个片段的完整元数据与判决理由
```

若使用者提供了标注，输出目录名换成人名（`taiga/`、`ryuuji/`），未匹配上的仍用 `speaker_NN`。

这是一个**聚类**工具，不是分类工具：说话人数量与身份都未知，使用者事后才命名分组，甚至可以不命名（ADR-001）。目标单位是**角色**而非声优（ADR-002）。下游是音色模型，**不涉及文本**（ADR-003）。

## 2. 端到端管线

```
                    ┌──────────────────────────────────────────┐
输入：视频 + 字幕   │  原始音轨（保持 44.1/48 kHz，永不丢弃）  │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
              1.    │ separate   人声分离                      │  ← 缓存
                    └──────────────────┬───────────────────────┘
                                       │
              ┌────────────────────────┴────────────────────────┐
              │ 判别轨（16 kHz mono 临时副本）                   │
              │                                                 │
     2.  ┌────▼─────────┐   3.  ┌──────────────┐                │
         │ diarize      │       │ subtitles    │                │
         │ 说话人轮次   │  ×    │ 台词时轴     │  → 候选片段     │
         │ + 重叠标记   │       │（可选先验）  │                │
         └────┬─────────┘       └──────────────┘                │
              │                                                 │
     4.  ┌────▼─────────┐                                       │
         │ embed        │  每个片段一个说话人嵌入               │  ← 缓存
         └────┬─────────┘                                       │
              │                                                 │
     5.  ┌────▼──────────────────────────────────────┐          │
         │ cluster                                    │          │
         │  a) 集内聚类（diarization 已给）           │          │
         │  b) 跨集链接：对集内 cluster 质心再聚类    │          │
         │  c) 估计说话人数量（阈值 / eigengap）      │          │
         └────┬───────────────────────────────────────┘          │
              │                                                 │
     6.  ┌────▼─────────┐  ← few-shot 标注在此介入               │
         │ assign/name  │                                       │
         └────┬─────────┘                                       │
              └─────────────────────┬───────────────────────────┘
                                    │  只传递「时间戳 + 分组 id」
                    ┌───────────────▼──────────────────────────┐
     7.             │ review   人工听样本，命名 / 合并 / 拆分  │
                    └───────────────┬──────────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────────┐
     8.             │ quality  重叠 / DNSMOS / 时长 / 削波闸门 │
                    └───────────────┬──────────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────────┐
     9.             │ export   从原始采样率音轨按时间戳切片    │
                    └──────────────────────────────────────────┘
```

**贯穿全流程的红线（ADR-004）**：判别轨只用于分析，向下游传递的只有**时间戳与分组 id**。音频本体永远从原始采样率的音轨走，绝不从降采样副本升回去。这条搞错会让成品静默报废。

## 3. 数据模型

全流程围绕**一张逐阶段增列的表**，`data/<show>/segments.parquet`：

| 列 | 产生阶段 | 说明 |
| --- | --- | --- |
| `seg_id` | segment | 主键 |
| `episode`, `start`, `end` | segment | 相对原始音轨的时间戳 |
| `source` | segment | `sub` / `diar` / `both`，记录这一段的来源 |
| `overlap` | diarize | 是否与其他说话人重叠 |
| `local_cluster` | diarize | 集内说话人 id |
| `emb_path` | embed | 嵌入缓存位置 |
| `global_speaker` | cluster | 跨集链接后的全局分组 |
| `assigned_name` | assign/review | 使用者给的名字，可为空 |
| `dnsmos_bak`, `dnsmos_sig` | quality | 背景干扰、语音失真 |
| `duration`, `clip_rate`, `lufs` | quality | 基础音频指标 |
| `decision`, `reject_reason` | quality | `accept` / `uncertain` / `reject` |
| `pipeline_hash` | 全程 | 处理路径标识，见 4.7 |

每个阶段是纯函数（读表、加列、写表），可单独重跑，可断点续跑，可直接用 pandas 检查。聚类和 review 会被反复迭代，而分离与嵌入只算一次，这个结构让重跑成本正确地落在便宜的那几步上。

## 4. 各阶段要解决的问题

### 4.1 ingest

抽音轨，**不做任何重采样**。同时生成一份 16 kHz 单声道副本供分析用，标记为临时文件。

### 4.2 separate

去掉 BGM 与音效。**全量走同一条处理路径**，不逐条择优（ADR-006）：两条路径混在一个数据集里会让音色模型学到不一致的伪影，一致性比单条片段的绝对质量更重要。

去混响默认关闭。场景混响确实会被音色模型学进去，但去混响本身也引入伪影，需要 A/B 听感对比后再决定。

### 4.3 segment

以 diarization 为准，字幕作辅助先验（ADR-007）。两个信息源的对比：

| | 字幕时轴 | diarization |
| --- | --- | --- |
| 覆盖 | 只有台词，漏掉惊呼、笑声、喘息等**对音色很有价值的非台词发声** | 全覆盖 |
| 边界 | 常有 100 到 300 ms 偏移，一行可能跨两个说话人 | 贴合实际语音 |
| 说话人 | 无 | 有（集内） |
| 重叠 | 无 | 有 |
| 成本 | 免费 | 需要推理 |

字幕用于**校验**：某段 diarization 轮次若完全落在字幕空白处，多半是背景杂音或音效残留，降权或标记。`source` 列记录每段来源，方便事后分析两者贡献。

### 4.4 diarize

产出说话人轮次与重叠标记。必须**先分离人声再 diarize**，顺序不能反。

要清醒的一点：公开 DER 数字来自会议、播客、广播域。经验规律是干净双人录音的说话人归属正确率能到 95% 以上，三人以上带重叠会掉到 75% 到 85%。动画一集常有 5 到 10 个角色，落在后一档。**diarization 的输出是待修正的草稿，不是终判**，4.6 节的人工修正是设计的一部分而非补丁。

### 4.5 embed + cluster

分两层（ADR-008）。第一层用 diarization 的集内结果；第二层对每个集内 cluster 的**长度加权质心**做凝聚层次聚类（余弦距离，average linkage），实现跨集链接。

用**距离阈值** $\theta$ 而非固定 $k$ 切树，因为说话人数量未知。$\theta$ 是整个工具最关键也最难盲选的超参数，三种定法按可得性排序：

- **有 few-shot 标注**：用标注算类内与类间距离分布，取使 B-cubed F1 最大的 $\theta$。
- **无标注但要自动**：用 eigengap 或轮廓系数扫一遍 $\theta$，取拐点。
- **兜底**：给一个经过标定的默认值，并在 review 阶段暴露滑块让使用者实时看分组数变化。

**长尾主动放弃（ADR-010）**：低于 `min_speaker_duration`（默认 60 s）的分组并入 `_misc/`。

短片段的嵌入不可靠，`duration < 1.0 s` 的段不参与聚类决策，只被动跟随所在轮次。

### 4.6 review：合并与拆分是核心功能

diarization 与聚类必然出错，而且错法是**系统性**的，不是随机的。设计必须假定使用者要修正：

| 错误类型 | 成因 | 修正操作 |
| --- | --- | --- |
| 同一角色被拆成多组 | 音区差异大（平静 vs 吼叫）、有变声处理（电话、机械音）、幼年与成年版本 | **合并** |
| 不同角色被并成一组 | 同一声优分饰多角、音色确实相近 | **拆分** |
| 歌声独立成组 | 插入曲、角色歌，人声分离会保留 | 标记丢弃或单独归档 |
| 旁白独立成组 | 信道不同（干声、无环境音） | 通常是正确行为，命名即可 |

所以 review 不是「看看结果」，而是一个必须做得顺手的编辑器：听代表样本、命名、拖动合并、按嵌入距离拆分、调阈值实时预览。

代表样本的挑选：取距离质心最近的若干条，同时保证时长和场景有一定分散，避免全挑同一场戏。

### 4.7 quality + export

闸门按重要性排序：

1. **重叠语音 → 拒收。** 音色数据集对重叠零容忍，也是最难事后排查的污染。
2. **背景干扰分过低 → 拒收**（检测 BGM 残留）。
3. **语音失真分过低 → 拒收**（检测分离伪影）。
4. 时长不在 $[1.0, 12.0]$ s → 拒收或切分。
5. 削波率、DC offset、响度离群 → 拒收。

阈值不要凭直觉写死，用首次运行得到的分布加人工听感标定。被拒片段进 `_rejected/` 并记录 `reject_reason`，不直接删除，方便发现闸门设错。

导出时从原始采样率音轨按时间戳切片，首尾各留约 50 ms padding，统一响度归一但避免削波。`pipeline_hash` 记录这一批用的分离检查点、是否去混响、闸门阈值等。当成品出现音色不一致时，这一列是唯一能定位问题批次的东西。

## 5. 已知失败模式

这一节比选型更重要，因为这些是设计必须**容纳**而不是消灭的东西。

| 失败模式 | 严重度 | 应对 |
| --- | --- | --- |
| 一个声优在同作品分饰多角 | 高，且自动方法无解 | 只能靠 review 拆分；文档明确说明 |
| 同一角色多种声线（变身、附身、幼年） | 高 | review 合并；UI 提示「这两组距离很近」 |
| 重叠语音 | 高 | diarization 重叠检测强制拒收 |
| 歌唱段落 | 中 | 检测伴奏 stem 能量，高能量区间的人声标记为疑似歌唱 |
| 非台词发声（惊呼、笑、喘） | 中，且**对音色有价值不该丢** | 依赖 diarization 而非字幕分段，正是为此 |
| 电话 / 广播 / 机械音滤镜 | 中 | 会自成一组，review 时决定合并还是单独保留 |
| 人声分离伪影 | 中 | 质量闸门的失真分；必要时换检查点或做 ensemble |
| 集数少时跨集链接不稳 | 中 | 质心层聚类已缓解；集数 < 3 时提示结果不可靠 |
| 预训练嵌入的域偏移（真人语音 → 动画配音） | 未知，需实测 | 双模型对比；必要时用伪标签做域适配微调 |

## 6. 评估

评估要贴合用途，不要套 DER 这种需要昂贵参考标注的指标。

**低成本协议**：在一部动画里随机抽约 200 个片段人工标注说话人，然后算：

- **B-cubed F1**（主指标）：对每个片段 $e$，精确率是其所在分组中与 $e$ 同真实身份的比例，召回率是同真实身份的片段中落在 $e$ 所在分组的比例，两者对全体取平均后求调和平均。它同时惩罚过度合并与过度拆分，正是聚类场景的两类错误。
- **各分组纯度**：导出的 `speaker_NN/` 里真正属于该人的比例。这是使用者真正关心的数字。
- **产量**：每个主要角色导出的净时长。音色收集通常 10 到 30 分钟就够，够了就不必再优化召回。

**不追求**：accuracy（无意义）、DER（成本过高且与用途脱节）。

前身仓库现有的 95 + 215 条标注片段可以立刻当作迷你评估集。

## 7. CLI 与仓库结构

每个子命令对应一个阶段，读写同一张表，可单独重跑：

```bash
avs ingest    --show toradora --video "ep*.mkv" --subs "ep*.ass"
avs separate  --show toradora
avs diarize   --show toradora
avs embed     --show toradora
avs cluster   --show toradora [--enroll labels/]     # few-shot 可选
avs review    --show toradora
avs export    --show toradora -o out/
avs run       --show toradora                        # 一条龙
avs doctor                                           # 环境自检
```

### Embedder 接口

```python
from typing import Protocol
import numpy as np
import torch


class Embedder(Protocol):
    dim: int

    def encode(self, wav: torch.Tensor, sr: int) -> np.ndarray: ...

    @property
    def signature(self) -> str: ...  # 进缓存 key，模型换了缓存自动失效
```

换模型 = 换一个实现类，聚类、评估、CLI、缓存层完全不动。
