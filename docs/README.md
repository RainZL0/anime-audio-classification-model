# 文档导航

## 先读哪个

第一次接触这个项目，按这个顺序看：

1. [`../README.md`](../README.md) —— 这工具是干什么的，怎么装
2. [`GLOSSARY.md`](GLOSSARY.md) —— 会碰到的专业词，每个一句话解释
3. [`HOW_IT_WORKS.md`](HOW_IT_WORKS.md) —— 它是怎么做到的
4. [`STATUS.md`](STATUS.md) —— 现在做到哪了，接下来做什么

想知道「为什么不用另一种做法」，看 [`DECISIONS.md`](DECISIONS.md)。

**准备动手改东西之前，先扫一眼 [`HISTORY.md`](HISTORY.md)。** 那里记着试过不行的路，
省得重走一遍 —— 已经有过「主唱分离」「声纹一致性检测第一版」这类白花的功夫。

## 每份文档管什么

一件事只在一个地方写，别的地方只放链接。不然两边迟早会说不一样的话。

| 文档 | 写什么 | 不写什么 | 多久改一次 |
| --- | --- | --- | --- |
| [`../README.md`](../README.md) | 这工具是什么、怎么装、一句话说明现在到哪一步、文档入口 | 任何细节 | 很少 |
| [`GLOSSARY.md`](GLOSSARY.md) | 专业词的大白话解释和英文原名 | 别的都不写 | 遇到新词才加 |
| [`HOW_IT_WORKS.md`](HOW_IT_WORKS.md) | 流程怎么走、每步在解决什么问题、哪里容易出错、怎么判断做得好不好 | 具体用哪个模型、进度、选择的理由 | 很少 |
| [`TOOLS.md`](TOOLS.md) | 用了哪些库、哪些模型、哪个版本，为什么选它 | 流程结构、进度 | 一般 |
| [`STATUS.md`](STATUS.md) | 现在到哪了、下一步做什么、卡在哪、还没想清楚的问题 | 设计、选型、**已经不成立的旧结论** | 经常 |
| [`DECISIONS.md`](DECISIONS.md) | 做过哪些选择、当时的理由、代价是什么 | 现状、计划 | 只往后加，不改旧的 |
| [`HISTORY.md`](HISTORY.md) | **试过不行的路**、被推翻过的结论、以及为什么会错 | 还成立的东西 | 每次有想法失败时加一条 |
| [`OLD_PROJECT.md`](OLD_PROJECT.md) | 上一版项目哪里错了，当作「别再犯」的清单 | 本项目的任何内容 | 不再改 |

## 不是文档但要知道的

[`../annotations/`](../annotations/) 放**人工标注**，也就是人给出的真答案。它跟 `runs/` 里的产物不一样：产物能重跑出来，人工标注不能，所以它会进 git。格式和用法见那个目录里的 `README.md`。

## 改文档的约定

- **换了模型或者库**：改 `TOOLS.md`。如果这个改动影响到流程结构，再改 `HOW_IT_WORKS.md`，并且在 `DECISIONS.md` 后面加一条。
- **进度变了**：只改 `STATUS.md`。`README.md` 里只有一句话状态，跟着阶段走。
- **推翻了之前的某个选择**：`DECISIONS.md` 里**不要改旧条目**，往后加一条新的，然后把旧那条的状态改成「已被第 N 条取代」。想法怎么变的，本身就是有用的信息。
- **发现同一段内容出现在两个文档里**：挑一个当正主，另一处改成链接。
- **某个结论被推翻了**：`STATUS.md` 里**直接删掉旧的写新的**，别在原地贴「此条已撤销」——
  那样文档会越滚越长，接手的人得先分辨哪句还算数。推翻的过程搬去 [`HISTORY.md`](HISTORY.md)，
  决策层面的变化在 [`DECISIONS.md`](DECISIONS.md) 后面加一条。
- **`STATUS.md` 超过 200 行**：说明留档混进现状了，把过期的部分搬去 `HISTORY.md`。
- **写法**：不用行话。专业词第一次出现时用大白话解释，或者直接指向 `GLOSSARY.md`。判断标准是：一个没做过语音的人能不能读懂。
