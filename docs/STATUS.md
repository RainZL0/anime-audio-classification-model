## 一句话

**整条流程跑通了，两集能产出按人分好的成品目录。** 卡了最久的「一条片段里好几个人先后说话」用字幕切割解决了（第 2 集 46 条人工标注里一条多人片段都没有）。分组的好坏分 0.930。**剩下的主要缺口是「两个角色被并成一组」，这类错自动的修不了，要等第 5 阶段的人工界面。** 素材是 Uma Musume S2 全 13 集，目前跑了第 1、2 集。

## 现在能跑什么

```bash
uv run avs doctor                                   # 检查环境

# 一集一条龙：抠人声 -> 切段认人 -> 整理片段 -> 按字幕切开 -> 音质筛选
uv run avs probe data/raw/uma_s2_01.flac --name ep01 \
  --subs "data/ass/uma/[FLsnow][UmamusumeS2][01][HEVC_FLAC][BDRIP].chs.ass"

uv run avs embed runs/probe/ep01                    # 算声音指纹
uv run avs group runs/probe/ep01 runs/probe/ep02    # 分组，跨集连接，快，可反复调
uv run avs export runs/groups.json --out out/uma_s2 # 导出成品

uv run avs label runs/probe/ep01 --mode names       # 人工标注（要视频）
uv run avs multi runs/probe/ep01                    # 评估用：试几种多人片段检测办法
```

`group` 和 `export` 分开，是因为分组几秒钟就跑完、会反复调分界线，而导出要重新读音频。

**改完代码要过的四项检查**见 [`../CLAUDE.md`](../CLAUDE.md)。

## 流程每一步的实测成绩

两集，Uma Musume S2 第 1、2 集。

| 步骤 | 第 1 集 | 第 2 集 |
| --- | --- | --- |
| 切段认人 | 说话 966 秒 | 说话 892 秒 |
| 整理候选片段 | 180 段 605 秒 | 204 段 607 秒 |
| **按字幕切开** | **242 段 514 秒（留 85%）** | **243 段 473 秒（留 78%）** |
| 音质筛选（留 50% + 绝对下限） | 121 条 266 秒 | 121 条 239 秒 |

**耗时**（RTX 4060 Laptop）：抠人声 815 秒（占 93%，1.8 倍实时），切段认人 62 秒，其余都是秒级。整季 13 集约 2.6 小时，跑一次就够。

### 字幕对齐

字幕配的是视频，跟音轨差一个固定偏移，**每集自己量**（把「字幕在显示」和「模型认为有人说话」两条时间线错开着比，看何时重合最多）。

| | 量出的偏移 | 重合度 |
| --- | --- | --- |
| 第 1 集 | -0.95 秒 | 0.744 |
| 第 2 集 | -0.96 秒 | 0.702 |

**防错位的闸验过了**：拿错集数的字幕重合度只有 0.42 到 0.45，全被 0.6 这条线拦住。但注意**拿错时不是接近 0 而是 0.42** —— 任何一集动画的说话密度都差不多，随便错开也能蹭上四成，所以余量只有 0.15 左右，换作品要重新量这张表。

**只在 BDRIP 那批字幕上验过**（第 1 到 4 集）。第 5 集起是 WEBRIP，偏移几乎肯定不一样。

### 声音指纹

两集独立的人工看画面标注，结论几乎一样：

| | 片段 | 角色 | 分得开程度 | 分界线 | 声纹错误率 |
| --- | --- | --- | --- | --- | --- |
| 第 1 集 | 25 | 11 | 0.9815 | 0.59 | 7.0% |
| 第 2 集 | 46 | 20 | 0.9839 | 0.63 | 5.9% |

**这个 0.6 是「两条片段之间」的尺子，不是分组用的那把**，别搬混（`HISTORY.md` 2.5 记着搬混的后果）。

### 分组

两层，两把不同的尺子（`stages/cluster.py` 里有完整的扫描表）：

| 层 | 比什么 | 分界线 |
| --- | --- | --- |
| 第一层：集内把片段聚成组 | 单条片段 | 0.55 |
| 第二层：中心点跨集合并 | 中心点 | 0.25 |

**第一层不用 pyannote 判断「这段是谁」，只用它切段**（决策 24）。效果：

| 第一层怎么做 | 分组好坏分 | 第 2 集正式组纯度 |
| --- | --- | --- |
| 用 pyannote 的分组 | 0.733 | 0.68 |
| **自己的指纹重聚一遍** | **0.930** | **0.80** |

分组好坏分同时惩罚「该合的没合」和「该分的没分」，样本是两集 75 条人工标注、3 个角色跨集出现。

### 成品

`out/uma_s2/`：6 个组加 `_misc`，243 条共 506 秒，**44.1 kHz PCM_24**，响度统一到 -23 LUFS 且不削顶，另有 `manifest.parquet` 记录每条从哪一集第几秒来。

**两集试听时要加 `--misc-seconds 20`。** 默认的 60 秒门槛是按 13 集定的，只跑两集会把大部分组吃进 `_misc`。

## 素材和环境

**素材**：`data/raw/uma_s2_01.flac` 到 `uma_s2_13.flac`，Uma Musume S2 全 13 集，44.1 kHz 立体声 FLAC，一集约 24 分钟，共 2.8 GB。选 FLAC 是因为原采样率无损、`soundfile` 能直接读（m4a 读不了）、体积只有 wav 的一半。

**字幕**：`data/ass/uma/`，FLsnow 版，全 13 集，简繁各一份。**第 1 到 4 集配 BDRIP，第 5 到 13 集配 WEBRIP。** 源视频是压进画面的硬字幕，没有内嵌字幕轨，这些是外挂找来的。

**人工标注**：[`../annotations/`](../annotations/)，会进 git，是目前唯一的真答案。`ep01_v4.json` 35 条、`ep02.json` 46 条。`runs/`、`data/`、`models/`、`out/` 都被忽略，删了能重跑。

**环境**（`uv run avs doctor`）：torch 2.11.0+cu128、CUDA 可用、RTX 4060 Laptop、pyannote.audio 4.0.7、audio_separator 0.47.0。

## 搭环境时踩到的坑

留档，免得换机器重装时再踩一遍。

- **`audio-separator` 有个没声明的依赖**：import 时需要 `audioread`，但它自己的依赖列表里没写。已手动加进本项目依赖。
- **torch 必须按操作系统分开装**（决策 11）：第一次生成锁文件解出了 torch 2.14 配 torchaudio 2.11 这种不兼容组合，现在两个都钉死在 2.11。
- **pyannote 4.x 在 Windows 上不能直接喂文件路径**：它内部用 `torchcodec`，而 `torchcodec` 要 FFmpeg 的**动态库 DLL**，常见的 gyan.dev essentials 版只有静态 exe。解法是自己把波形读成张量再传进去，见 `probe.py` 的 `diarize()`。
- **`onnxruntime-gpu` 和 torch 的 CUDA 版本对不上**：装的是按 CUDA 13 编的，torch 是 cu128，启动会刷一屏 `cublas64_13.dll` 找不到。目前不影响，因为选定的模型走 torch；但 WeSpeaker 那条走 onnxruntime，只能按 CPU 跑。
- **HuggingFace 门禁**：`speaker-diarization-community-1` 和 `wespeaker-voxceleb-resnet34-LM` 点过同意就能用，但 `pyannote/segmentation-3.0` 是**另一个独立门禁的仓库**。用 `HfApi.model_info` 读得到元数据**不等于文件可下载**。目前不影响，community-1 自带分段模型。
- **代码检查工具的三条规则对中文是误报**：`RUF001/002/003` 会把中文全角标点全判成同形字攻击，已关闭。`docs/` 也排除出格式化范围。
- **终端是 GBK**：直接 print 中文到管道会报 `UnicodeEncodeError`。写脚本时加 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`。
