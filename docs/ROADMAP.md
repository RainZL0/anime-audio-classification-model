# 初版路线

更新：2026-10-18。这里写到初版发布为止的目标、方向和标准；眼前的下一步在 [STATUS.md](STATUS.md)。「方向」还没经过独立检验；「标注界面」已经做出第一版，怎么运转见 [HOW_IT_WORKS.md](HOW_IT_WORKS.md#标注与修正界面)。

## 目标

- 做成值得公开发布的工具，目标是 GitHub 上 1000 星。
- 主要用户：想给某个角色训练语音模型（GPT-SoVITS、Style-Bert-VITS2、RVC 等），需要这个角色干净的单人语音的人。其次是想找出某个角色全部台词的人。
- 同类工具几乎都没有「改错之后模型跟着变好」这一步，详见 [COMPETITORS.md](COMPETITORS.md#5-我们能占据的空位gaps-we-can-own)。

## 仓库

- 初版在本仓库本地开发，发布前不推送。
- 发布时替换 GitHub 上旧仓库 `RainbowZL0/anime-audio-classification-model` 的 `main`：先给旧 `main` 打标签保存，再把本仓库的历史推上去。沿用旧仓库是为了保留已有的星和链接；要不要改名，发布前再定。

## 方向

- **输入**：每集的视频和字幕都必须有，缺一样就拒绝处理。字幕决定怎么切片段，视频给标注者认人。
- **认人**：声纹模型不动，在人工标签上训练一个小分类器，把片段直接分到角色名下。小分类器几秒就能训完，所以每改一条标签都可以马上重训。每条预测附带把握大小：把握高的直接采用，把握低的进待确认，跟谁都不像的标成未知或新角色。
- **为什么可能比分组好**：分组拿一条片段去比另一条片段，两边都有噪声，还要靠一个全局分界线，而这个分界线会随池子大小漂移（[依据](EXPERIMENTS.md#分界线漂移)）。分类拿一条片段去比一个角色的几十条片段，而且每个角色有自己的界线。
- **起步**：用现有分组（错误合并少，但分得碎）让人给整组起名字，一次就能标一批。
- **以后再做**：利用前后台词的顺序、字幕文字、画面里的口型。标签攒到几千条，再考虑微调声纹模型，那时要先改 [DECISIONS.md](DECISIONS.md#已经定下的) 里「不微调模型」那一条。

## 标注界面

已经做出的第一版（快捷键见 [USAGE.md](USAGE.md#标注与修正界面)）：

- **起步分组**：没有标签时，给机器分出的组起名字，一次标一整组。
- **场景**：台词按场景排成对话，每个角色有固定的头像和颜色，左边放画面、台词和机器猜的前三名，每个候选附参考音。拿不准的片段原计划单独一个视图，现在并进场景，用「只看要处理的」筛出来。
- **角色**：某个角色的全部预测按把握从低到高排，可以连着播，挑出不对的，其余一键确认。也在这里改名、合并、设头像。
- **操作**：键盘为主，大多数时候按 Enter 就是接受预测，数字键对应底部固定顺序的角色。每一步都能撤销。「不止一个人」「无法确认」「不是说话」是特殊标签；「路人」这类多人共用的名字可以关掉训练。
- **跟谁都不像**：机器发现一句和已知角色都不像时，提示「可能是没见过的人」，不硬给名字。
- **数据**：每次标注只往记录里追加。只拿人确认过的标签训练。这些标签和打分用的检验集分开，规矩见 [HISTORY.md](HISTORY.md#标注) 的标注第 3 条。

还没做的：第一次使用的引导、空工作区和出错时的提示、在界面里添加新的一集（现在要先用命令行 `prepare`）。

## 初版发布标准

1. **检验**：按集留出检验，分类明显好于分组，数字写进 README。
2. **标注界面**：给整组起名字、场景和角色两种看法、键盘操作、撤销、改完马上重训。第一版已做出，待打磨。
3. **导出**：至少支持 GPT-SoVITS 的清单格式，带台词文字。已支持 GPT-SoVITS、Style-Bert-VITS2 和按角色分文件夹，文字取自字幕（格式见 [COMPETITORS.md](COMPETITORS.md#2-训练端期望的数据集格式)）。训练日语模型要日语原文；如果字幕是译文，就要加日语语音转文字，这会改动 DECISIONS 里「不加语音转文字」那一条，动手前先定。
4. **安装**：`uv sync` 一条命令装好。Windows 一键包可以放到初版之后。
5. **README**：开头一张演示动图，一句话说清用途，中日英三种语言。许可已定：代码用 MIT，提取内容的使用范围写在 README 的「使用规范」一节。MIT 本身允许商用，所以「不得商用」约束的是提取出的内容，不是代码。

## 发布

- 先找大约 10 位目标用户试用，修好问题，再在 Bilibili、知乎、V2EX、Reddit、Hacker News、X 同一天发布。
- 在日本，声优的声音授权是敏感话题。README 写清用途边界，宣传重点放在整理和检索台词上。
