# 人工身份标签

这些文件来自人对照视频确认角色，不能靠重跑恢复，必须保留。

- `ep01_v4.json`：35 条旧边界片段，25 条单人身份、9 条多人、1 条无法确认。
  2026-09-06 经标注者确认，本文件的 `红毛` 与 ep02 的 `Nice Nature` 是同一角色，已统一为 `Nice Nature`（文件内 `renamed` 字段记录）。两集是分别标注的，跨集同一角色必须用同一个名字，否则评估会把它们当成两个人。
- `ep02.json`：46 条角色身份标签。
  2026-09-06 经标注者确认，本文件里的解说是两个不同的人，`解说` 与 `解说2` 已改为并列的 `解说A` 与 `解说B`（文件内 `renamed` 字段记录），避免被读成同一个人的两种写法。
- `ep01-full.json`、`ep02-full.json`：两集全部片段的重标（ep01 242 条、ep02 243 条）。这是当前唯一的验收真值。
  改成整集连着标，是因为抽样标注每条都要重新定位画面，费的力气大半花在找位置而不是认人上，而且抽出来的范围不够覆盖候选改动的片段。
- `legacy/`：重构前的现场姓名记录、早期听音分组记录及抽样上下文。保留备查，不能把 `labels_groups` 当身份真值。

`ep01_v4.json` 与 `ep02.json` 的逐条标签不再计入验收，两份文件继续保留：里面的角色名是标注页词表的来源，片段还能在页面上回放，用来想起某个名字是谁。人工记录不删。

`name` 是人名；`__multiple__`、`__unclear__`、`__not_speech__` 是特殊标签；`null` 表示尚未标注。评估只精确匹配同一音轨和时间范围，不把旧片段标签猜着迁移到新边界。

新增标注命令见[根 README](../README.md)。

每次提交直接保存到这里，不再等关闭服务才从被忽略的 runs 目录归档。已有归档会继续使用；边界不同则要求新文件名，不能覆盖旧人工工作。
