# 人工标注

这个目录放**人工标注**，也就是人给出的真答案。

## 为什么单独一个目录

流程跑出来的东西都在 `runs/` 底下，而 `runs/` 被 `.gitignore` 忽略了，因为那些都是重跑一遍就能再有的产物。

**人工标注不是产物。** 它是人花时间听、花时间看画面标出来的，删了就没了，重来一次要几十分钟。所以单独放在一个会被 git 跟踪的地方。`data/` 也在忽略列表里，所以没放那儿。

## 每份文件长什么样

一个文件对应一次标注任务，文件名跟着 `runs/` 里那次测试的目录名走（比如 `ep01_v4.json` 对应 `runs/probe/ep01_v4/`），这样代码能直接对上。具体是哪一集看文件里的 `source` 字段。

```json
{
  "source": "...uma_s2_01_(vocals)_....flac",   // 哪个音轨
  "run": "runs/probe/ep01_v4",                  // 哪次测试抽的样
  "labelled_on": "2026-09-06",
  "method": "看画面报名字（avs label --mode names）",
  "note": "...",
  "clips": [
    {
      "clip_id": "clip_03",
      "start": 5.38, "end": 8.165, "stamp": "00:05.4",
      "machine": "SPEAKER_09",   // 机器（切段认人）给的标签
      "name": "旁白",             // 人看着画面给的名字，真答案
      "by_ear": "A"              // 更早只靠耳朵标那轮的结果，只作对照
    }
  ]
}
```

**`name` 是唯一可信的那一列。** 它来自人在动画里跳到那个时间点、看画面上是谁在说，不是靠听。

**`by_ear` 别当真答案用。** 那是更早一轮只靠耳朵分组的结果，一集有 9 个说话人时人记不住，35 条里 17 条被标成「听不清」。留着是为了记录这个工具设计上的教训，见决策 18。

三个特殊值，不是人名：

| 值 | 意思 |
| --- | --- |
| `__multiple__` | 这条片段里不止一个人在说话 |
| `__unclear__` | 听不清 / 判断不了 |
| `__not_speech__` | 不是说话 |

`null` 表示这条还没标。

## 怎么再标一份

```bash
uv run avs label runs/probe/<某次测试> --mode names
```

标完按 Ctrl+C，它会自动往这个目录写一份归档。干活时的临时文件仍然留在 `runs/` 底下，那些是可以随便删的。

`avs embed` 会优先读这个目录里的归档，读不到才去找 `runs/` 里的现场文件。
